Looking at both the E22-900T30D datasheet constraints and the ESP32-S3 N16R8 pin reservations before making a recommendation.

  The ESP32-S3 N16R8 has several GPIO ranges to avoid:
  - GPIO6–11: Internal Quad Flash
  - GPIO33–37: Octal Flash/PSRAM (the N16R8 uses both, so these are consumed)
  - GPIO0, 3, 45, 46: Strapping pins — avoid for M0/M1 especially, since their state at boot affects startup behavior

  Suggested assignments:

  ┌───────────────┬───────────────┬───────────┬────────────────────────────────────────────────────┐
  │    E22 Pin    │ ESP32-S3 GPIO │ Direction │                     Rationale                      │
  ├───────────────┼───────────────┼───────────┼────────────────────────────────────────────────────┤
  │ TXD (E22→ESP) │ GPIO18        │ Input     │ UART1 RX                                           │
  ├───────────────┼───────────────┼───────────┼────────────────────────────────────────────────────┤
  │ RXD (ESP→E22) │ GPIO17        │ Output    │ UART1 TX                                           │
  ├───────────────┼───────────────┼───────────┼────────────────────────────────────────────────────┤
  │ AUX           │ GPIO4         │ Input     │ Interrupt-capable; use to detect module busy/ready │
  ├───────────────┼───────────────┼───────────┼────────────────────────────────────────────────────┤
  │ M0            │ GPIO5         │ Output    │ Clear of strapping and flash pins                  │
  ├───────────────┼───────────────┼───────────┼────────────────────────────────────────────────────┤
  │ M1            │ GPIO21        │ Output    │ Clear of strapping and flash pins                  │
  └───────────────┴───────────────┴───────────┴────────────────────────────────────────────────────┘

  A few things worth knowing before wiring:

  Power: At 30 dBm (1 W) the E22-900T30D can draw ~700 mA peak during transmission. Don't power it from the ESP32-S3's onboard 3.3 V regulator — give it a dedicated supply capable
  of the peak current. The logic I/O is 3.3 V compatible so no level shifting is needed.

  AUX behaviour: AUX goes low while the module is busy (transmitting, receiving, changing config). It's worth wiring it to an interrupt-capable pin (all the ones above qualify) so
  you can use gpio_isr_handler rather than polling.

  M0/M1 at boot: Since M0/M1 are outputs driven by the ESP32-S3, they'll float briefly during reset. If the E22 latches mode on power-up before the ESP32 drives them, add 10 kΩ
  pull-downs to default to normal UART mode (M0=0, M1=0) during the boot window.

● Good news: the code already sets E22TxPower::DBM21 in make_config() — that's the minimum the T30D supports, so power is already as low as it goes.

  For tests, here's what's worth running to fully validate the modules:

  1. Packet error rate (PER)
  Send N packets from A, count how many B receives. The industry standard acceptance threshold is <1% PER. Most useful test for link reliability.

  2. Round-trip latency statistics
  Timestamp each ping/echo and compute min/max/average/jitter over ~100 samples. Gives a baseline to compare against if you change air rate or antenna later.

  3. Noise floor
  Enable rssi_noise on both modules and sample the ambient RSSI with no transmission. Tells you how clean the 900 MHz channel is in your environment.

  4. Air rate sweep
  Run the PER test at K1_2, K2_4, K9_6, and K19_2. Documents the speed/reliability tradeoff for your specific environment.

  5. Maximum payload
  Send 200-byte packets (the default sub-packet size limit). Verifies framing doesn't break at the boundary.
